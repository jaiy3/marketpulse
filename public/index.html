How it works

  1. Ingest. A worker holds a WebSocket to Binance and validates every trade with Zod. Bad messages are dropped, and the connection reconnects with exponential backoff.
  2. Cache and fan out. Each trade becomes the latest price in Redis (30-second expiry, so stale prices disappear) and is published on Redis pub/sub, so any number of API instances can push it to their WebSocket clients.
  3. Persist off the hot path. Writes go through a BullMQ queue with retries. Job IDs are derived from symbol and second, so duplicates and replays never create extra rows.
  4. Serve. REST reads come from Redis (latest) or an indexed PostgreSQL query (history). Rate limiting, JWT auth, Prometheus metrics and health checks are built in.
